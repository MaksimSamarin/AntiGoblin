# AntiGoblin 1.4.3

## VPN-группа по умолчанию

В настройках появилась галочка **«VPN-группа по умолчанию»**. При включении
домашний сегмент получает политику `xkeen`: новые устройства по Wi-Fi и кабелю
подключаются к правилам AntiGoblin независимо от регистрации. Найденные в
домашнем сегменте существующие устройства переводятся на наследование;
исключения `no_vpn`, запрещённые клиенты и другие сегменты сохраняются.

Для включения сначала выберите активный ключ и сохраните настройки. Галочка
применяется сразу. Предыдущие назначения сохраняются для восстановления при
выключении; более поздний ручной выбор `no_vpn` остаётся исключением.

При установке или обновлении создаётся отсутствующая политика Keenetic
**`no_vpn`**. Существующая политика и её настройки не перезаписываются.
Само обновление не переводит домашнюю сеть в `xkeen`. Если привязка уже была
включена в Keenetic, галочка отобразит её текущее состояние.

`xkeen` использует правила выбранного профиля: галочка не означает отправку
всего трафика через VPN. Гостевая сеть настраивается отдельно. Подробности и
ограничения переноса офлайн-клиентов — в [описании политик](../device-policy.md).

Проверены создание и сохранение `no_vpn`, включение/выключение, исключения,
повторная установка, откат при ошибке, защищённый API и интерфейс на тестовом
контуре. Локальный патч проверен на реальном роутере; после установки
пользователь подтвердил галочку и работающий YouTube по Wi-Fi.

Включены исправления [1.4.2](v1.4.2.md) и [1.4.1](v1.4.1.md). Если старая
обновлялка останавливается с `nohup: not found`, для первого перехода
установите в Entware `coreutils-nohup` и повторите обновление.

## English

The **Default VPN group** checkbox enrolls the home segment in `xkeen`.
New wired and Wi-Fi devices inherit AntiGoblin routing rules, including
unregistered devices. Identified existing home clients adopt segment
inheritance; `no_vpn` overrides, blocked clients and other segments are retained.
Choose and save an active key before enabling. Changes apply immediately,
with prior assignments recorded for restoration when disabling.

Installation and updates create a missing `no_vpn` policy without overwriting
an existing one. Updating alone does not enroll the home network. The checkbox
reflects an existing native binding when already enabled. Profile routing rules
still decide which destinations use VPN. See [device policies](../device-policy.md)
for offline-client and recovery details. Older updaters failing with
`nohup: not found` need `coreutils-nohup` once to install this release.
